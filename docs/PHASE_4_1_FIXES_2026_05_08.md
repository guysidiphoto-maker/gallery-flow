## What was wrong before Phase 4.1

Phase 1-3 closed the storage anon-DELETE exploit, the silent-save UX hole, and the plain-text PIN. But the audit's #2 critical finding remained open: **the `gallery-images` bucket is fully public, and originals (20.8 GB / 87% of bytes) are downloadable by anyone with a guessed gallery_id**.

Flipping the bucket private without preparation = mass image 401s during a customer event = catastrophic. Phase 4.1's job: build the infrastructure for the future flip in parallel, in pieces, without risk.

The specific gaps Phase 4.1 closes:

1. **Drift in URL construction**: 5 places in the codebase hardcoded `${SUPABASE_URL}/storage/v1/object/public/...` strings instead of going through the `storageUrl()` helper. Any future signed-URL swap would have to grep + manually fix each.

2. **No signed-URL helper**: there was no async layer that could request a short-lived URL from a server endpoint and fall back to public. We had to build one.

3. **No server endpoint** to issue signed URLs that verifies the caller's identity (per Phase 3's session token).

4. **No design** for the hardest piece: anonymous gallery viewers who don't have a session token (`/<biz>/<gallery-slug>` opened from a WhatsApp link).

5. **No plan** for upload-pipeline dual-write (the new public-thumbs bucket + the existing private bucket).

6. **No plan** for the AI flows that fetch images via public URLs (`score-images.ts`, `rekognition/index.ts`).

7. **No QA framework** for a 30-test acceptance suite + rehearsed rollback.

#### Agent 4.1.B — Signed URL Infrastructure

**Files**: NEW `gallery-web/src/lib/signedStorage.ts` (94 lines), modified `gallery-web/api/append-event-posts.ts` (+57 lines)

**Frontend helper** (`signedStorage.ts`):
```ts
export async function signedStorageUrl(
  bucket: string,
  path: string,
  options?: { token?: string; bypassCache?: boolean; fallbackToPublic?: boolean }
): Promise<string>
```
- 55-minute in-memory cache (signed URLs are 60-min server-side; 5-minute safety margin)
- In-flight de-dup: 10 simultaneous calls for the same `(bucket, path)` trigger ONE network roundtrip
- Falls back to existing public URL if the endpoint fails (preserves today's behavior)
- Reads session token from sessionStorage automatically OR accepts explicit `options.token`
- Also exports `clearSignedUrlCache()` for logout flows

**Backend action** (added to `/api/append-event-posts`):
- New `action: 'signed_url'` body shape: `{ bucket, path }`
- Validates: bucket is in allowlist (`gallery-images`, `gallery-stories`, `demo-uploads`), path doesn't contain `..` (prevents traversal)
- Calls `supabase.storage.from(bucket).createSignedUrl(path, 60 * 60)` — works on both public and private buckets
- Token-aware: if `X-Client-Session` header present, verifies via Phase 3's `verify_client_token` RPC; logs warning on mismatch (advisory mode for now)
- Returns `{ ok: true, url, expires_at, token_present }`

**Risk**: 🟢 **Helper is unused, action is opt-in**. Backwards-compatible. Stays within Vercel's 12-function cap (uses dispatcher).

### Plan-only deliverables (no code)

#### Agent 4.1.C — Public Viewer Session Design

**Doc**: `docs/PHASE_4_PUBLIC_SESSION_DESIGN.md` (2,500 words)

**The puzzle solved**: how does an anonymous customer (opening `/<biz>/<gallery-slug>` from WhatsApp on their phone) load images after the bucket flips private? They have no session token, no PIN.

**The proposal**:
- New `action: 'public_gallery_session'` on `append-event-posts.ts` (no new endpoint file).
- New `public_gallery_sessions` table (separate from Phase 3's `client_session_tokens` — different security model).
- Token: 32-byte opaque, gallery-scoped, IP-issued, 60-min TTL.
- Anti-abuse: 30 sessions/IP/hour soft (Turnstile challenge), 100/hour hard ceiling.
- Cloudflare Turnstile **free tier** is 60× our scale.
- Frontend: `useEffect` in `App.tsx` calls `ensurePublicSession(galleryId)` before any image render, caches in sessionStorage, silently refreshes at minute 50.
- Mid-scroll expiry handled invisibly: `signedStorage.ts` re-issues lazily on cache miss.
- Cutover: gated by `VITE_PUBLIC_VIEWER_SIGNED_URLS=1` env flag; ships in Phase 4.5.

**Effort**: 3.5 engineering days + 1.5 buffer = **5 days**.

#### Agent 4.1.D — Upload Pipeline Dual-Write Plan

**Doc**: `docs/PHASE_4_UPLOAD_DUAL_WRITE.md`

**The plan**: when the new public-thumbs bucket exists, every new upload writes the thumb to BOTH buckets (private original + public thumbs). Backfill existing 71 galleries × ~250 thumbs = ~17,750 copies.

**Specifics**:
- Hook at `uploadPipeline.ts:150` — replace single `uploadOne(BUCKET, thumbPath, …)` with `Promise.all` writing to both buckets. Public-bucket failure is best-effort (captured as a boolean), not throwing.
- New migration 044: adds `images.public_thumb_present BOOLEAN DEFAULT false` and a new `p_public_thumb_present` RPC parameter so failed second-bucket writes are knowable + reconcilable.
- Backfill: Supabase Edge Function on a 5-min cron, copying ~50 thumbs per run, ~7.5 hours total runtime, +$0.02/month storage.
- Pure-SQL `storage.copy` does not exist — rejected.
- Bucket flip in Phase 4.5 gated on `SELECT count(*) FROM images WHERE public_thumb_present = false` returning 0.

**Effort**: 2 days code + 7.5 hours backfill (background) = **2-3 days**.

#### Agent 4.1.E — AI/Rekognition Compatibility Plan

**Doc**: `docs/PHASE_4_AI_REKOGNITION_PLAN.md`

**Findings**:
- Only **2 files** actually fetch image bytes: `gallery-web/api/score-images.ts` (Node) and `supabase/functions/rekognition/index.ts` (Deno).
- `generate-feed.ts`, `generate-campaign.ts`, `plan-event.ts` are **text-only** — they pass image-IDs around as JSON, never fetch bytes. **Zero changes needed**.

**The proposal**: send image bytes inline (base64 to Anthropic, raw `Uint8Array` to Rekognition) via `supabase.storage.download(path)` which uses service-role and bypasses RLS regardless of bucket privacy.

**Specifics**:
- New shared helper `gallery-web/api/lib/serverImageBytes.ts` (~80 LOC, parallel pool capped at 5 concurrent downloads).
- Deno edge function duplicates the 3-line pattern (different module system, no shared import).
- Net code delta: ~15 LOC in `score-images.ts`, ~3 LOC in `rekognition/index.ts`.
- Latency cost: +50-100ms/image (under 10% overhead, well under `maxDuration = 60s`).
- Bandwidth cost: ~$0/month (the bytes go from Supabase to our Vercel function and on to Anthropic — egress is negligible at our scale).

**Effort**: 1 day for both files. Cutover during Phase 4.4 is per-endpoint and reversible while bucket remains public.
